## 2. 独立发现（C-1..C-5）

### C-1（阻断）AC-13 无对应用例，且"非本机来源"在现有 E2E 夹具下不可构造

- 规格 AC-13：「`/api/*` 在**非本机来源**且无凭据时返回 `401`」。
- 测试规格 §2 的 E 用例清单里**没有**任何一条覆盖 AC-13；覆盖表里只写了"AC-13"字样（集成 L2 行），属**声明而非用例**。
- 更要命的是可执行性：E2E 夹具把实例绑在 `127.0.0.1`，**所有请求的 `client_address` 必然是 127.0.0.1**，永远走"本机免鉴权"分支 → AC-13 在该夹具下**物理不可测**。
- **要求**：给出可执行的构造方式并落成用例。可行路径有两条（应同时采用）：
  1. **单元层**：把鉴权判定抽成可注入 `client_ip` 的纯函数，用假 client IP（如 `192.168.1.50`）直接断言判定结果——不依赖网络拓扑，最稳；
  2. **E2E 层**：夹具改绑 `0.0.0.0`，用本机非回环地址（如 `socket.gethostbyname(socket.gethostname())`）访问；取不到非回环地址时该用例 `skip` 并在报告里显式标注。

### C-2（阻断）AC-12 的前置定义缺失："登录事件"的日志结构未定义

- AC-12 要求"登录成功/失败写入请求日志"，但 PRD 只说"复用 `log_request`（`:165`）"。
- `log_request(entry)` 消费的是固定 schema 的 entry（`_request_log` 环形缓冲 + `log_request_to_disk` 落 JSONL），PRD **没有定义登录事件的 entry 形状**（字段名、是否含 username、是否含来源 IP、是否含口令）。
- 没有 schema → 测试无法写断言 → AC-12 不可测；同时实现者可能把口令写进日志（违反 P3）。
- **要求**：PRD 明确登录事件 entry schema，并显式规定**禁止记录口令与完整 Cookie**。

### C-3（阻断）CLI 语义歧义，直接影响 Lane 契约

- 规格 S8 写的是 `--reset-password <username>`；Architect §3 建议改成"由运维显式设置初始口令"。二者语义不同：
  - `--reset-password` 前提是**用户已存在**；
  - 引导场景是**用户尚不存在**。
- PRD 未定义："用户不存在时 `--reset-password admin` 是报错、还是创建？"——Lane A 的 `set_password` 返回 `bool`、Lane C 的 CLI 行为都会因此分叉。
- **要求**：统一为一个自洽命令族并写死语义（建议 `--set-password <username>`：存在则轮换，不存在则创建；`--reset-password` 作为其别名或直接废弃）。

### C-4（非阻断但需补）备选方案缺少中间形态与成本量级

- 方案 C 被否时只说"不满足需求本体"。若要公平，应给出成本量级对比，并补一个中间形态 **C′：复用 `tap-` key 作为唯一凭证 + 增加 `name`/审计字段，不引入口令哈希**。
- 若 C′ 能以"3 行改动 + 无新存储"达到 80% 需求，则"方案 A 需要新增 1 个文件 + 口令哈希 + 会话表 + 登录页"就是**可量化的额外成本**，必须让用户（ODL）看到这个对比。
- **要求**：PRD 增加 C′，给出三者成本矩阵，并把它连同 ODL-1/ODL-3 一起交给用户确认。

### C-5（阻断）运行期回退路径不可执行

- `--no-login` 是**启动参数**（PRD §6 AC-14），而线上实例是**已运行**的（PID 26124）。
- 一旦上线后用户被锁在外（忘记口令 + 无账号文件备份），唯一手段是"停服务 → 改文件 → 启服务"，而这属于破坏性操作，README 需写明**精确步骤**。
- **要求**：给出一个**运行期**、非破坏性的回退（例如配置字段 `login.enabled=false` 落盘即时生效），并写进 PRD 与 README。
