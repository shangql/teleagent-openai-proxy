## 2. 逐轮记录

### R0 — 预检（不提问）

**结论**：brownfield 项目；已有 API Key 鉴权体系（`_auth_check`，`openai_proxy.py:339`）；控制台是内联 HTML（`:3431`）；线上实例 `0.0.0.0:8088` 裸奔；仓库零依赖、零测试、零 CI。详见上下文快照 F1–F19。

### R1 — 意图："用户"是谁？

> **问（原文）**：这个项目要加的"用户登录"，登录的是**谁**？是坐在浏览器前操作控制台的人，还是调用 `/v1/chat/completions` 的程序（企微机器人 / Cursor / LangChain）？

**答〔默认·待用户确认〕**：
- 登录对象 = **控制台人类操作者**（账号体系叫 account）。
- `/v1` 的程序调用方**继续用 API Key**，不引入账号概念。

**依据**：
- 仓库唯一的"人"入口是 `/console`（`README.md:142`）。
- `/v1` 侧已有完备的 Key 机制：三种模式、加盐哈希、签发/停用/过期（`openai_proxy.py:203-382`），重复造账号体系属于双重真相源。
- 现有接入方（`README.md:138`）都是程序，强行要求账号会破坏 C2。

**该轮歧义**：0.575 → 0.415。

### R2 — 范围与非目标

> **问（原文）**：这次**明确不做**哪些事？（我先给一版，你删改）

**答〔默认·待用户确认〕**：
- ❌ 不做 JWT（理由在 RALPLAN-DR 里展开，属方案选择而非范围问题）。
- ❌ 不做**多角色/权限系统**（admin/viewer 之外的细粒度授权）。
- ❌ 不做**按用户配额/计量**（每人 token 上限、账单）。
- ❌ 不做**自助注册**（账号由管理员创建）。
- ❌ 不做**邮件找回密码**（零依赖下不现实）。
- ❌ 不改 `/v1` 的鉴权模型（保持 `off/partial/strict` 三档不变）。
- ✅ 做：账号存储（口令哈希）、登录会话、登录页、控制台与管理面接入登录态、CLI 重置口令、测试、文档与发布。

**依据**：`README.md:269` 零依赖是产品卖点；C2 不得打断本机机器人；无邮件依赖则找回只能走 CLI。

**该轮歧义**：0.415 → 0.318。

### R3 — 约束（压力测试：证据式确认）

> **问（原文，按仓库既有术语对撞）**：我看到 `/api/*` 目前对**本机来源免鉴权**（`openai_proxy.py:353`），而本机的企微机器人正是靠它回确认消息（`/api/permission/reply`）。这次做登录，**这条本机免鉴权要不要保留**？

**答〔默认·待用户确认〕**：**保留**。
- 本机免鉴权 = 本机信任边界，与"谁登录控制台"是两件事。
- 关闭它会打断本机机器人的 `POST /api/permission/reply` 流程（C2）。
- 但**登录态是并行凭证**：非本机来源访问 `/api/*` 必须持有效会话 Cookie 或有效 API Key。

**其余约束**：
- C1 零依赖 → 口令哈希用标准库 `hashlib.pbkdf2_hmac`（`scrypt` 在 Windows 上受内存限制，不如 pbkdf2 稳）。
- C3 不打断线上实例 → 验证一律在**副本目录 + 备用端口**上做。
- C5 双平台 → 只用跨平台标准库 API。

**该轮歧义**：0.318 → 0.253。

### R4 — 验收标准（可测试化）

> **问（原文）**：做到什么程度算"可以上线"？请挑一条能当场演示的判据。

**答〔默认·待用户确认〕**（可当场演示、可自动化断言）：
1. `GET /console` 未登录 → `302` 到 `/login`；带有效会话 → `200`。
2. `POST /api/auth/login` 口令错误 → `401`；正确 → `200` + `Set-Cookie`（HttpOnly + SameSite=Lax）。
3. `POST /api/auth/logout` 后，原 Cookie 立即失效（`/console` 回到 `302`）。
4. `/v1/chat/completions` 行为**不变**（现有机器人不受影响）。
5. 口令在 `auth_users.json` 中**只以加盐哈希落盘**，明文不落盘。
6. 同一 IP 连续 5 次失败 → 第 6 次 `429`。
7. `python -m unittest discover tests` 全绿；`py_compile` 无错。

**该轮歧义**：0.253 → 0.180（数值首次达标）。

### R5 — 决策边界

> **问（原文）**：剩下的分歧项，哪些我可以自己定、哪些必须回来问你？

**答〔默认·待用户确认〕**：见上下文快照 §8。**必须问用户**的 7 项已转写为 ODL（见第 4 节），未获答复前一律按"推荐默认"实现，并保证**可一行回滚**。

**该轮歧义**：0.180 → 0.143。

## 3. 挑战模式（各一次）

### Contrarian（挑战核心假设，R2 之后）

**质疑**："用户要的是『加登录』这个功能，还是『别让人随便用我的机器』这个问题？"
**证据**：线上实例 `--host 0.0.0.0`（F12/F14），README 自己写着"用 `0.0.0.0` 会把本机 TeleAgent 的调用能力暴露给整个局域网"（`README.md:84`），而 `auth.json` 的 `mode` 是 `off`（F9）。
**结论**：**主因是暴露面，不是缺登录页**。真正的处置顺序应为：① 绑定 `127.0.0.1`（收窄暴露面）→ ② 登录做纵深防御 → ③ 审计。
**对规格的影响**：登录功能按"纵深防御的一层"定位；并在发布检查清单里把"监听地址"列为**上线前必答项**，而不是偷偷替用户改掉线上参数。

### Terminologist（brownfield 必用）

**撞车术语**：`session`（仓库已用于 super-agent 会话）、`auth`（已用于 API Key）、`用户`（人 or 程序）、`上线`（本机 vs 云）。
**结论**：登录会话一律叫 **login session**（代码 `login_session`）；账号体系叫 **account**；机器凭证叫 **api key**；"上线"在本项目 = **本机服务跑到新代码 + `main` 合入**。全链路用词统一，禁止再出现裸 `session` 指代登录态。

### Simplifier（压到最小可行范围，R4 之后）

**发现范围膨胀风险**：初版设想包含多角色、自助注册、per-user 配额、JWT 双模式。
**结论**：全部砍掉。MVP = **单管理员引导 + CLI 增删用户 + 会话登录保护控制台**。理由：先让"身份边界"成立，再谈"身份之上"的策略。砍掉的项进入 **Backlog（v2）**，不删除。

### Ontologist（症状 → 本质，R3 之后歧义 0.253 > 0.25 触发）

**重构**：症状 = "没有登录功能"；本质 = **"这台机器上没有身份边界：谁是人、谁是机器、谁能碰管理面，全靠监听地址决定"**。
**结论**：把需求重述为「**建立身份边界**」，登录是其中"人"的一层；同层还有"机器凭证"（已有 API Key）、"暴露面"（监听地址）、"审计"（登录事件落日志）。
**对规格的影响**：规格的"意图"一节按此重述；验收标准里加入一条——**登录成功/失败必须进请求日志**（复用现有 `log_request` 落盘，`:165`）。

## 4. Open Decision Ledger（ODL）— 必须由用户拍板

> 每条：**问题原文** / **推荐默认（本次实现采用）** / **改选的影响** / **证伪条件**。
> 未确认前，实现按推荐默认落地；发布检查清单会逐条回问。

| ID | 问题原文 | 推荐默认（已采用） | 改选的影响 | 证伪条件 |
| --- | --- | --- | --- | --- |
| ODL-1 | 「用户」是控制台的人，还是调用 `/v1` 的程序？ | 人（account）；程序继续用 API Key | 若程序也要账号 → 需把 `tap-` key 绑定 user_id 才能计量，范围 +1 档 | 用户明确要"每个机器人一个账号并单独计费" |
| ODL-2 | JWT 还是 session？ | **服务端 session**（Cookie）；JWT 否决 | 改 JWT → 手写 HS256（无 PyJWT）+ 无法即时吊销 + 单机无横向扩展需求 | 出现多实例/跨机鉴权需求 |
| ODL-3 | 要多用户 + 角色吗？ | 支持多用户，角色只分 `admin` / `viewer` 两级 | 要更细 → 需权限矩阵与端点级校验 | 用户要"按角色隐藏控制台某个页签" |
| ODL-4 | 要按用户计量/配额吗？ | **不做**，进 v2 backlog | 要做 → 需 `/v1` 侧按 user 聚合 token 用量并落库 | 用户说"要防止某个 key 把额度跑爆" |
| ODL-5 | 密码忘了怎么办？ | CLI 重置：`python openai_proxy.py --reset-password admin` | 要自助找回 → 需邮件/短信依赖，破 C1 | 用户要求"不登录机器也要能改密码" |
| ODL-6 | `/api/*` 本机免鉴权要不要关？ | **保留**（机器人依赖它） | 关掉 → 本机机器人 `permission/reply` 断链 | 机器人迁移到别的机器 |
| ODL-7 | 登录会话要不要跨重启保留？ | **不保留**（纯内存，8h TTL） | 保留 → 会话令牌需落盘 = 新增令牌泄露面 | 用户抱怨"每次重启都要重新登录" |
| ODL-8 | 监听地址要不要一并收窄到 `127.0.0.1`？ | **代码不改线上参数**，仅在发布清单里提示 | 直接改 → 会打断局域网访问方 | 无 |
